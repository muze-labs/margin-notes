# Cobalt fragments in RDF

Margin notes owns the bridge in
[`cobalt-fragment-rdf.js`](../src/features/paragraph-note-stacks/cobalt-fragment-rdf.js).
Cobalt receives and returns its plain `{ text, annotations }` value. It has no
Turtle, OLDM, workspace, or storage dependency. OLDM parses and writes Turtle;
Solid Workspace persists the resource graph.

## Stored shape

```turtle
@base <https://book.example/chapter> .
@prefix note: <https://book.example/chapter#margin-note-Abcd1234-> .
@prefix cobalt: <https://vocab.muze.nl/cobalt#> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix oa: <http://www.w3.org/ns/oa#> .
@prefix dcterms: <http://purl.org/dc/terms/> .

note:1 a oa:Annotation ;
    dcterms:modified "2026-10-30T12:00:00Z" ;
    oa:hasBody note:1-html ;
    cobalt:fragment note:1-fragment ;
    oa:hasTarget <#paragraph> .

note:1-fragment a cobalt:Fragment ;
    rdf:value "Bold text" ;
    cobalt:annotations ( note:1-fragment-0 ) ;
    dcterms:hasFormat note:1-html .

note:1-html a oa:TextualBody ;
    dcterms:format "text/html" ;
    rdf:value "<strong>Bold</strong> text" .

note:1-fragment-0
    cobalt:start 0 ;
    cobalt:end 4 ;
    cobalt:tag "<strong>" ;
    cobalt:order 1 .
```

The `cobalt:` terms are an application convention, not a Solid standard or a
new dependency of Cobalt. The existing namespace is retained; this document
specifies the mapping used here without claiming a published ontology.

| Value | Meaning |
| --- | --- |
| `rdf:value` on the fragment | Exact Cobalt text, stored as a string literal, including URI-looking text. |
| `dcterms:hasFormat` | Links the editable fragment to its generated HTML body. |
| `rdf:value` on the HTML body | HTML generated by Cobalt’s renderer, stored as a string literal with `dcterms:format "text/html"`. |
| `cobalt:annotations` | One ordered RDF list, represented by an OLDM Collection. Duplicates and sequence are preserved. |
| `cobalt:start`, `cobalt:end` | Cobalt's half-open UTF-16 code-unit range, stored as integer literals. |
| `cobalt:tag` | Exact Cobalt tag string, such as `<strong>`, `</strong>` or `<a href="…">`. |
| `cobalt:order` | Integer formatting precedence; independent of list position. |

An empty list is `()` / `rdf:nil`. OLDM currently parses it as a named `rdf:nil`
node, which the bridge accepts and writes canonically. Non-empty lists use
`oldm.Collection`; ordinary arrays of RDF values are rejected as unordered.
Integer literals may have lexical string wrappers after parsing; the bridge
validates their datatype and converts them to Cobalt numbers. Invalid ranges,
missing fields and old JSON fragment literals are reported, not migrated.

## Editor boundary

The application can use the bridge with Cobalt's existing value API:

```js
import oldm from '@muze-nl/oldm';
import {
  readCobaltFragment, writeCobaltFragment,
} from './src/features/paragraph-note-stacks/cobalt-fragment-rdf.js';

const graph = oldm.context().parse(turtle, resourceUrl, 'text/turtle');
editor.setValue(readCobaltFragment(graph.get(fragmentId)));

const savedFragment = writeCobaltFragment(editor.getValue(), { id: fragmentId, htmlId, graph });
const outputTurtle = await graph.write();
```

These are application module exports, not additions to the Cobalt package API.
`writeCobaltFragment(fragment, { id, htmlId })` builds a detached native graph,
useful when constructing new annotation input for the workspace. With a graph,
it creates or updates the fragment and its HTML body, returning the fragment node.
The annotation links to the fragment through `cobalt:fragment` and to the HTML
through `oa:hasBody`. The model updates the annotation timestamp,
and asks SimplySolid to save the annotation's resource. The bridge performs no
I/O. `readCobaltFragment()` returns a fresh editor value; it does not detach or
replace authoritative RDF nodes.

## Edits and replicas

Margin notes keeps one current fragment per note, with no revision history.
New fragment IDs append `-fragment` to the annotation ID; formatting members
append `-<index>`. The resource's single random code lives in the `note:` prefix,
so a fragment is `note:1-fragment` and its first member is `note:1-fragment-0`.
The Collection supplies formatting order. Editing reuses the fragment and member
IDs, replaces their mapped fields, and clears mapped fields from removed members.
Unknown predicates and additional types are preserved. Removed members with no
remaining facts disappear from output; those with unknown facts remain detached.
Invalid editor values are rejected before the graph is changed.

Only the annotation carries a modification timestamp. The app declares
`cobalt:fragment`, `dcterms:hasFormat` and `cobalt:annotations` as owned links.
The annotation owns the fragment, which owns its HTML and formatting members.
`oa:hasBody` is a reference to the same HTML body, not a second ownership edge.
The links, format, plain text, generated HTML, Collection and formatting fields
are scalar replacement predicates. Solid Workspace selects those fields together using the annotation's
timestamp, preventing stale replicas from reintroducing removed markup. Empty
Collections represent no owned members. This is whole-note replacement for a
single-user app, not collaborative editing or revision storage.

The app does not rewrite identifiers or sweep old snapshots already stored by
previous test builds. The app recognizes the current annotation-level fragment
link; earlier body-to-fragment test data is not migrated. Edits within the current
shape reuse the fragment and HTML body.
Unknown RDF remains additive. Conditional remote writes and concurrent creation
remain outside this change.

## Interoperability

A reader can follow `oa:hasBody` to an `oa:TextualBody`, inspect its `text/html`
format and read its single `rdf:value` without understanding Cobalt. This follows
the [Web Annotation embedded textual body model](https://www.w3.org/TR/annotation-model/#embedded-textual-body).
The fragment's [dcterms:hasFormat](https://www.dublincore.org/specifications/dublin-core/dcmi-terms/terms/hasFormat/)
link describes the alternative representation; edit ownership is app policy.
No custom HTML predicate or RDF HTML datatype is needed on this standard body.

The editable fragment is authoritative. Cobalt's renderer generates HTML on every
write; the app does not parse that HTML back into editing annotations. Raw text
and generated HTML deliberately coexist for interoperability. No extra body
modification timestamp or revision history is stored. This model is exercised
with an OA-only reader test; it is not a claim of full Web Annotation conformance.

## Evidence

- `test/cobalt-fragment-rdf.test.js`: Turtle round trips, sequence, duplicates,
  overlapping annotations, Unicode, empty lists, invalid inputs and independently
  authored Turtle using different prefixes.
- `test/annotation-model.test.js`: native graph ownership, unknown facts and
  competing replica edits, including removal of all formatting.
- `test/browser-mounted.test.js`: actual Cobalt modal values and rendered
  formatting survive Turtle save/remount; an unformatted edit survives reload.
